# 经验总结与证据边界

记录日期：2026-10-25。来源为脱敏后的维护回执及两份旧 handover；未发布原始文件、个人资料、账户信息、任务 ID 或业务目录。历史报告中已被后续证据纠正的断言不继续作为事实。

| 经验 | 有效证据 | 结论边界 |
|---|---|---|
| 壳与 core 可分开升级 | 2026.9.5 → 2026.10.5 固定版本 Bun 本地安装成功 | 不保证任意壳/新 core 组合 |
| root CLI 可造成后续权限问题 | 老 handover 的具体 EACCES 定位 | 以应用身份运行 CLI；不推广 chown -R |
| 内置 backup 不是全系统镜像 | 归档索引曾未含 core/壳/runtime | 冷备需自己的 inventory |
| 元数据问题必须看恢复目标 | 同 tar 换隔离目录比对零差异 | 不把 chmod 差异写成 tar 不保存属主 |
| Node 有多个来源 | shell PATH 与 /proc exe 实际不同 | symlink 与 actual inode 分开核 |
| 异常读取不是 clear | /proc 权限失败、网络命名空间共享 | socket owner 只凭真实 FD 关联，未知保留未知 |
| “原样 16 PASS”曾跑错对象 | 绑定源码的 runner 才发现 38 项 fixture 错误 | 测试数不能代替源码身份；最终 38+2 离线通过仍不是生产恢复能力 |
| Preview 与正式模型 ID 可走不同 hook | 精确 matcher 与离线 payload 构造对照 | 普通回复成功不证明思考参数正确 |
| HOME 是运行依赖 | bridge 修复 HOME 后实际 embedding 200/1536 维 | 一次成功不等于全检索验收 |
| 运维 cron 不必用模型 | agentTurn 改 command 后本地观测正常 | 等待自然调度证据，不虚报长期稳定 |
| 文档本身也会导致返工 | 多轮旧规则互相覆盖 | 当前规则集中、原文归档、停止恢复旧自动化 |

## 应当停止重复做的事

不因内部 context/无 exec 停下已授权工作；不把每一小步重新变成审批；不为文档整理重跑模型或历史 40 项测试；不将 fake fetch、归档 checksum 或命令零退出等同完整服务验收。每次测试都应回答一个当前未解决的问题。

## 公开分享原则

案例版本、通用路径结构和问题机制可公开；原始配置、HOME 内凭据、真实任务 ID、进程环境、完整业务日志、私人 AGENTS/USER/MEMORY 不公开。共享 MD 不是要求其他用户采用同一模型、安静时段、投资偏好或调度策略。

新公开脚本只作离线验证，不沿用历史“生产验证通过”的标签。后续若有人在不同 fnOS 包上运行，请报告包版本、匿名布局和必要错误，不贴秘密。提交新补丁须记录适用 core/壳 hash、最小 diff、失败边界、回退和实际验收。
